# S02: ROCE and ROE derivation — UAT

**Milestone:** M001
**Written:** 2026-09-20T10:55:20.128Z

## UAT Type

- UAT mode: browser-executable
- Why this mode is sufficient: This slice extends a backend JSON API; verification is via direct HTTP checks against the running proxy, observable without a frontend. Browser tooling (or curl-equivalent HTTP calls) against localhost is sufficient since no UI exists yet (S03 will add it).

## Preconditions

- Start the proxy: `cd server && npm run dev` (or equivalent start script) → serves on `http://localhost:<port>` (see server/src/index.ts for port, typically 3000)
- No API keys required (Yahoo Finance unofficial API)

## Smoke Test

Navigate to `http://localhost:3000/api/stock/RELIANCE.NS` and confirm the JSON response includes `roce` and `roe` fields (numeric or null), in addition to the S01 fields (marketCap, currentPrice, week52High, week52Low, peRatio, bookValue, dividendYield).

## Test Cases

### 1. Valid ticker returns computed ROCE/ROE
1. Navigate to `http://localhost:3000/api/stock/TCS.NS`
2. Inspect the JSON body
3. **Expected:** `roce` and `roe` are present as numbers (or null if upstream data was incomplete), alongside all S01 fields; HTTP 200.

### 2. Repeat lookup served from cache
1. Navigate to `http://localhost:3000/api/stock/TCS.NS` twice within 5 minutes
2. **Expected:** Both responses return identical roce/roe values quickly (cache hit), no duplicate upstream calls logged.

## Edge Cases

### Invalid ticker
1. Navigate to `http://localhost:3000/api/stock/NOTATICKER.NS`
2. **Expected:** Existing 404 not-found behavior from S01 is unchanged; no roce/roe fields expected.

### quoteSummary upstream failure (simulated by unreachable network or invalid modules)
1. Force quoteSummary to fail internally (not user-triggerable directly, but observable via server logs)
2. **Expected:** Response still returns HTTP 200 with the other 6 S01 metrics populated and `roce`/`roe` as `null`; server logs the quoteSummary failure without crashing.

## Failure Signals

- roce/roe missing entirely from JSON (should be null, not absent)
- Server crash or 500 response when quoteSummary fails (should degrade gracefully)
- tsc errors or failing unit tests (already verified: 0 errors, 8/8 tests passing)

## Not Proven By This UAT

- No UI exists yet to visually confirm the metrics (S03 will add the Angular dashboard)
- Live network behavior against Yahoo's actual quoteSummary endpoint under real-world rate limiting/outage conditions is not exercised here beyond code-level try/catch behavior

## Notes for Tester

Unit-level correctness of the ROCE/ROE math itself is already proven by 8 passing automated tests in server/src/finance.test.ts; this UAT focuses on confirming the values surface correctly through the live HTTP route with proper degradation on failure.

## Operational Readiness

- **Health signal**: Server logs a message on quoteSummary failure (mirrors existing quote() error logging); successful requests return roce/roe populated in the JSON body.
- **Failure signal**: Repeated null roce/roe across many tickers combined with logged quoteSummary errors indicates a systemic upstream issue (e.g., Yahoo API schema change or outage).
- **Recovery**: No automatic retry; each request independently attempts quoteSummary again. No circuit breaker — acceptable at this scale since failure is isolated to two optional fields per request.
- **Monitoring gaps**: No metric/counter for quoteSummary failure rate; only ad-hoc console logs. Acceptable for current single-proxy, local-dev-stage scope.
