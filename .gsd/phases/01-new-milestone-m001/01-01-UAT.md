# S01: Proxy foundation and core valuation metrics — UAT

**Milestone:** M001
**Written:** 2026-09-19T20:15:39.266Z

## UAT Type
- UAT mode: runtime-executable

## Preconditions
- From server/: `npm install` then `npm run dev` (tsx watch on src/index.ts), listening on http://localhost:3000
- Requires outbound network access to Yahoo Finance endpoints (finance.yahoo.com, query1/query2.finance.yahoo.com) that is not rate-limited

## Steps & Expected Outcomes
1. `curl http://localhost:3000/health` → 200 `{"status":"ok"}`
2. `curl http://localhost:3000/api/stock/RELIANCE.NS` → 200 JSON with marketCap, currentPrice, week52High, week52Low, peRatio, bookValue, dividendYield all present as numbers (not null)
3. Repeat step 2 immediately → same response served from cache (check server console log shows `[cache HIT]` instead of `[cache MISS]`, and the response is effectively instantaneous)
4. `curl http://localhost:3000/api/stock/NOTAREALTICKERXYZ` → 404 JSON `{"error":"Ticker not found"}`
5. Simulate upstream failure (e.g. network cut mid-request, or Yahoo rate-limiting as observed in this sandbox) → 502 JSON `{"error":"Upstream fetch failed"}`, server process stays alive

## Edge Cases
- Upstream rate-limiting (HTTP 429 "Too Many Requests" from Yahoo) is treated as a 502, not a crash — confirmed repeatedly in this sandbox environment
- Missing individual fields on the Yahoo response should not throw; defensive mapping should substitute reasonable fallbacks (e.g. dividendYield falling back to trailingAnnualDividendYield) rather than failing the whole request

## Known Limitation
Live 200-path with real numeric values has not been confirmed from this sandbox's network due to persistent Yahoo Finance rate-limiting across all verification attempts (T03, T04, closeout). Should be re-verified from an unthrottled network before/alongside S02.
