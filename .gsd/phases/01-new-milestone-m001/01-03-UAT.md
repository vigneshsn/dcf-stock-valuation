# S03: Dashboard UI and error handling — UAT

**Milestone:** M001
**Written:** 2026-09-20T12:50:40.137Z

## UAT Type
- UAT mode: browser-executable

## Preconditions
- Start the Express proxy (per S01/S02 setup) — typically `node server/index.js` or equivalent, listening on http://localhost:3000
- Start the Angular dev server: `npm run start` (or `npx ng serve --port 4200`) → http://localhost:4200
- Alternatively, run the automated smoke test: `npx playwright test` (auto-starts `npx ng serve --port 4200` via playwright.config.ts webServer block)

## Steps and Expected Outcomes
1. Navigate to http://localhost:4200/fundamentals — the ticker input and submit button are visible; initial state is idle (no error, no data grid).
2. Enter a valid ticker (e.g. RELIANCE.NS) and submit — a loading indicator appears, then either:
   a. A 9-field metrics grid renders (Market Cap, Current Price, 52-Week High, 52-Week Low, P/E, Book Value, Dividend Yield, ROCE, ROE), with any null/missing field showing "N/A", or
   b. If the upstream Yahoo Finance API is unreachable, an "Upstream data source failed, please retry" message appears with a Retry button (this was the observed live outcome in the sandboxed test environment).
3. Enter an invalid/nonexistent ticker (e.g. ZZZZINVALID.NS) and submit — the proxy returns 404, and the UI shows "Ticker not found" (no crash, no stale data grid).
4. Stop the Express proxy and submit a ticker — the UI shows a network-error message (no crash).
5. Click Retry after any error state — search() re-runs; state cycles through loading again.

## Edge Cases Covered
- Partial data: some metrics null/undefined → rendered as "N/A" per-field rather than failing the whole dashboard (verified via fundamentals.component.spec.ts null-field assertions, not manual DOM inspection).
- Invalid ticker (404) → distinct "not found" message (verified via HttpTestingController flush in unit tests and via live upstream-error path in Playwright smoke test).
- Upstream failure (502) → distinct "upstream" message with Retry (verified via unit test flush).
- Network/connection failure → distinct "network" message (catch-all branch).

## Automated Evidence
- `e2e/smoke.spec.ts` (Playwright): navigates to /fundamentals, submits a ticker, asserts a broad regex match (N/A|not found|failed|retry) becomes visible within 15s — passes whether the backend is reachable or not, proving the UI always reaches a terminal state.
- `src/app/services/stock.service.spec.ts` and `src/app/fundamentals/fundamentals.component.spec.ts`: assert HTTP call shape and 404/502/null-field state mapping without requiring a live server.

## Known Limitations
- No live-upstream "happy path" screenshot was captured in this environment since the sandboxed network path to Yahoo Finance was not reachable during closeout verification; the upstream-error path was exercised instead, which is a valid and expected terminal state per the smoke test design.
